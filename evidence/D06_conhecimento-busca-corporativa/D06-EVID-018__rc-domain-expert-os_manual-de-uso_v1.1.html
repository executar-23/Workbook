RC Cognitive Risk Expert

Especialista canônico do Mapa Interativo de Risco Cognitivo. Use esta skill para consultar, explicar, pesquisar, auditar, verificar claims, refatorar produto/conteúdo/design, produzir ADR/PRD e preparar handoffs de implementação sem perder a distinção entre ciência, decisão interna e framework proprietário.

02 · Modelo operacional

Como a skill funciona

Você não precisa conhecer os nomes dos arquivos internos. A skill classifica a intenção, resolve a fonte de verdade vigente e carrega apenas os módulos necessários.

REQUEST → INTENT → MODE → CANONICAL SOT → DOMAIN REFERENCES → CLAIM/EVIDENCE GATE → EXECUTION → QA → OUTPUT
Projeto

Source-first

Quando existe fonte canônica interna, a skill resolve essa fonte antes de responder. Memória do modelo não substitui o SOT.

Pesquisa

Research quarantine

Pesquisa externa nova entra como CANDIDATE_EVIDENCE. Ela não atualiza claims ou decisões vigentes automaticamente.

10 modos operacionais

CONSULT

Consultar a fonte de verdade vigente do projeto.

Qual é a tese vigente do produto?

Saída: ANSWER → SOURCE/STATE → LIMIT/CONFLICT → NEXT

EXPLAIN

Explicar conceitos assumindo zero conhecimento prévio.

Saída: PLAIN EXPLANATION → EXAMPLE → EVIDENCE STATUS → LIMIT

RESEARCH

Pesquisar evidência nova e compará-la com o SOT sem atualização automática.

Pesquise evidência nova sobre memória prospectiva e compare com o SOT.

Saída: QUESTION → CURRENT → NEW EVIDENCE → CONFLICT → RECOMMENDATION → REVIEW REQUIRED

CLAIM-CHECK

Validar se uma afirmação pode ser publicada.

Valide este claim: cada interrupção custa 23 minutos.

Saída: PASS / PASS_WITH_DISCLOSURE / REVISE / BLOCK

AUDIT

Auditar site, texto, design ou produto contra contratos vigentes.

Audite a página publicada contra ADR-001.

Saída: OBSERVED → CONTRACT → GAP → PRIORITY → EVIDENCE → RECOMMENDATION

REFACTOR

Refatorar preservando comportamento válido e autoridade canônica.

Refatore esta seção do site sem alterar os claims autorizados.

Saída: CURRENT → PROBLEM → DECISION → TARGET → DIFF → TESTS → RISKS → STATE

PRODUCT

Transformar decisões em ADR, PRD e requisitos estruturados.

Transforme esta decisão em ADR + PRD sem alterar claims.

Saída: DECISION / REQUIREMENTS / NON-GOALS / ACCEPTANCE / DEPENDENCIES

EDITORIAL

Criar ou revisar comunicação, narrativa e linguagem científica.

Reescreva esta seção para público leigo usando reconhecimento antes da terminologia.

Saída: CLAIM → EXPLANATION → EXAMPLE → CONSEQUENCE

DESIGN

Projetar visualização e interação sem aumentar causalidade ou magnitude implícita.

Como devo visualizar CLAIM-06 em scrollytelling?

Saída: VISUAL SEMANTICS → INTERACTION → ACCESSIBILITY → FALLBACK

IMPLEMENTATION-HANDOFF

Preparar instruções determinísticas para outro agente implementar.

Gere o handoff para implementar Story → Explore → Personalize.

Saída: AUTHORITIES → SEQUENCE → CLAIM MAP → TESTS → BLOCKERS → DOD

07 · Produto + UX · RC-MOBILE-QUERY-001

Consulta guiada · Mobile First

A interface canônica da consulta passa a responder quatro macros, em ordem determinística: Problema → Processo → Progresso → Ação. O mapa radial e o Knowledge Graph completo permanecem disponíveis como exploração avançada, não como porta de entrada.

CONSULTA → 01 RECONHECER → 02 ENTENDER → 03 ACOMPANHAR → 04 AGIR
01 · RECONHECER

Se o problema aparece como…

Comece por manifestações reconhecíveis. Não peça ao usuário para identificar “déficits” ou categorias técnicas.

02 · ENTENDER

O processo adequado é…

Mostrar apenas o caminho do Knowledge Graph relacionado à consulta atual. O usuário não precisa navegar no grafo inteiro.

03 · ACOMPANHAR

O progresso esperável será…

O gráfico responde somente ao que deve ser observado se a intervenção estiver ajudando. Não exiba oito variáveis simultaneamente.

04 · AGIR

Inicie por…

Toda consulta termina em uma primeira ação concreta e, no máximo, três passos executáveis.

Consulta ativa

04 · Inicie por
Reduzir uma troca evitável no próximo bloco de trabalho.
  1. Escolha uma tarefa dominante.
  2. Agrupe atividades semelhantes.
  3. Registre onde retomar antes de mudar de contexto.
Valores numéricos deste exemplo são ilustrativos e não representam resultado clínico ou individual. Dados reais devem trazer origem, unidade, período, método e evidence_refs.

Regra de produto

Uma consulta = um problema + um processo + um progresso esperado + uma primeira ação + três passos.
Complexidade do banco ≠ complexidade da interface.

07 · Claims

Como validar uma afirmação

O modo CLAIM-CHECK compara a frase com o registry, escopo, causalidade, certeza, disclosure de framework e linguagem proibida.

Exemplo seguro

@rc-cognitive-risk-expert valide este claim: “Trocar rapidamente de tarefa não significa trocar sem custo.”

Exemplo a bloquear/revisar

@rc-cognitive-risk-expert valide: “Cada interrupção custa 23 minutos de produtividade.”

08 · Pesquisa

Atualizar conhecimento sem destruir o SOT

1
Resolver CURRENT SOT.
Descobrir o que o projeto afirma hoje.
2
Pesquisar evidência nova.
Preferir fonte primária ou oficial e comparar o mesmo constructo/contexto.
3
Classificar como candidata.
A pesquisa não altera automaticamente o registry.
4
Apontar conflito e impacto.
Separar confirmação, ampliação, contradição e ausência de efeito.
5
Exigir review/change control.
Somente depois uma mudança pode virar canônica.
@rc-cognitive-risk-expert pesquise evidência nova sobre memória prospectiva, compare com o SOT atual e não atualize o registry automaticamente.

10 · Produto

ADR, PRD e decisões

Use PRODUCT quando a mudança altera arquitetura, comportamento, jornada, escopo ou requisitos. A skill separa evidência, decisão e implementação.

@rc-cognitive-risk-expert transforme esta decisão em ADR + PRD. Inclua non-goals, critérios de aceite, dependências, implicações nos claims e estados atual/alvo.
11 · Editorial + Design

Comunicar sem fortalecer claims

Para público leigo

A regra é reconhecimento antes da terminologia: situação reconhecível → termo → mecanismo → evidência → limite.

Para visualização

O visual deve expressar o claim sem adicionar magnitude, causalidade ou certeza que a fonte não sustenta. Sempre prever fallback legível/reduced-motion.

@rc-cognitive-risk-expert transforme CLAIM-06 em uma cena de scrollytelling para público leigo, com evidência, boundary e fallback sem animação.
12 · Estados

Não confundir existência com verificação

EXISTING ≠ COMPLETE ≠ APPROVED ≠ IMPLEMENTED ≠ TESTED ≠ VERIFIED ≠ RELEASED

A skill deve informar o estado real observado/documentado. Ela não pode chamar uma implementação de “verificada” sem teste e verificação.

13 · Invariantes

Regras que nunca devem ser quebradas

1
fator ≠ vulnerabilidade ≠ exposição ≠ risco.
2
Fator candidato não é risco confirmado.
3
Prioridade/ranking não é gravidade.
4
Não produzir diagnóstico clínico, score clínico ou causalidade não sustentada.
5
[FW] nunca pode ser apresentado como [E1], [E2] ou [S].
6
Existente ≠ completo ≠ aprovado ≠ implementado ≠ testado ≠ verificado ≠ released.
7
Redação autorizada no projeto não significa revisão externa por especialista.
8
Pesquisa web nova entra como candidate evidence até change control.
9
Quando há SOT interno, a skill não responde apenas de memória.
10
Reescrita, resumo, design ou implementação nunca podem fortalecer um claim.
14 · Testes

Smoke tests após instalação

Use estes cinco testes para confirmar que progressive disclosure, grounding e governança estão funcionando.

1
Qual a diferença entre fator e risco no projeto?
2
Valide: cada interrupção custa 23 minutos.
3
Explique task switching para alguém sem conhecimento prévio.
4
Audite o site publicado contra ADR-001.
5
Pesquise evidência nova e compare com o SOT sem atualizar automaticamente.
Esperado: source-first; resolução do claim registry; distinção framework/ciência; pesquisa externa em quarentena; estados de implementação sem falsa verificação.

SintomaVerificaçãoAção

Claim foi fortalecidoRodar modo CLAIM-CHECK e consultar claim-registry.csv.Usar a redação autorizada mais segura.
Pesquisa nova mudou o SOTVerificar se research.md e change-control.md foram carregados.Reverter para candidate evidence e abrir review.
Framework apresentado como ciênciaChecar etiquetas FW/E1/E2/S.Inserir disclosure obrigatório e corrigir o claim.
