Estruturei e executei essa evolução como um novo pacote operacional.

O ponto central do novo ADR é eliminar a necessidade de uma etapa intermediária “Figma-ready”. O repositório passa a ser a própria Source of Truth de Design: PRD/FRD/ADR → Golden Screens → Visual Contract → Tokens → Component Registry → React Design System → Rotas → /design-system → verificação → deploy.

O pacote contém:

  • ADR-CLAUDE-DESIGN-EXECUTION-001.md — governança completa da execução por Claude Design.
  • CLAUDE.md — regras persistentes para o agente trabalhar diretamente no Design System.
  • EXECUTE_DESIGN.md — comando standalone de execução ponta a ponta.
  • visual-contract.yml — contrato visual rota por rota.
  • component-registry.yml — inventário e estados dos componentes.
  • os 10 mockups como golden-screens.
  • tokens canônicos JSON + CSS, com projeção runtime dentro do app.
  • package React full stack em Next.js + React + TypeScript.
  • componentes reutilizáveis de navegação, descoberta, artigo, busca, salvos e preferências.
  • rotas /artigos, /explorar, /artigos/categoria/[slug], /artigos/[slug], /buscar, /salvos e /preferencias.
  • /design-system como showroom vivo para Claude Design e o time inspecionarem foundations e componentes diretamente no código.
  • /api/articles, /api/articles/[slug] e /api/health.
  • PWA manifest básico.
  • assets editoriais locais, sem dependência de imagens remotas.
  • persistência inicial de Salvos e Preferências em localStorage, permitindo primeiro deploy sem banco ou credenciais.
  • configuração para deploy Next.js/Vercel.
  • manifest do pacote, árvore de diretórios, checklist e relatório de verificação.

A verificação estrutural executada retornou VERIFY PASS: rotas obrigatórias, tokens, projeção dos tokens e arquivos essenciais estão consistentes. O npm run build não foi marcado como verificado porque o ambiente atual não possui os pacotes Next.js instalados e não foi possível validar o registry externo; portanto o estado correto é PARTIALLY_VERIFIED, e não um falso DONE.
